# TASK-1401: Publish environment-specific configuration references for API, portal, Windows agent, and Linux agent with secret provisioning separated from artifacts and command lines

## Objective

Publish environment-specific configuration references for API, portal, Windows agent, and Linux agent with secret provisioning separated from artifacts and command lines.

This task contributes to [EPIC-14: Operations And Release Readiness](../epics/EPIC-14.md)
and must preserve the epic outcome: Make the completed feature set observable, configurable, deployable, recoverable, and supportable in the selected first environment.

- [TASK-1007](./TASK-1007.md): Add disposable Ubuntu lifecycle automation for install, repeat install, upgrade, rollback, reboot/autostart, restart recovery, stop, uninstall, and retained state
- [TASK-1109](./TASK-1109.md): Define standalone portal build/start configuration, API base URL validation, forwarded headers, health/readiness, and deployment guidance

## Deliverables

- The production or decision artifact described in the objective.
- Focused automated tests or deterministic validation for the changed
  behavior.
- Updated contract, configuration, architecture, or runbook documentation
  where applicable.

## Acceptance Criteria

- Fresh-environment deployment succeeds using only documented variables and protected secret steps.
- All prerequisite behavior remains passing after this change.
- No credentials, API keys, refresh tokens, or sensitive configuration values
  are committed, persisted in plaintext, or emitted to logs.
- Failures are explicit and actionable; the implementation does not silently
  discard telemetry, authorization failures, migration errors, or installer
  errors.

## Validation

1. Run focused tests that directly falsify the objective if it is incomplete.
2. Run integration tests for every changed database, HTTP, authentication,
   queue, or process boundary.
3. Run platform packaging tests when Windows Service or systemd behavior is
   affected; a successful compile alone is insufficient.
4. Run portal lint, unit, browser, and automated accessibility checks when UI
   behavior is affected, followed by a manual keyboard review.
5. Run the repository-level build and the checks required by Gate 3.
