## Acceptance Criteria

- A failing test or build blocks its owning job; job output identifies the failed slice.
- All prerequisite behavior remains passing after this change.
- No credentials, API keys, refresh tokens, or sensitive configuration values
  are committed, persisted in plaintext, or emitted to logs.
- Failures are explicit and actionable; the implementation does not silently
  discard telemetry, authorization failures, migration errors, or installer
  errors.

## Validation

1. Run focused tests that directly falsify the objective if it is incomplete.
2. Run integration tests for every changed database, HTTP, authentication,
   queue, or process boundary.
3. Run platform packaging tests when Windows Service or systemd behavior is
   affected; a successful compile alone is insufficient.
4. Run portal lint, unit, browser, and automated accessibility checks when UI
   behavior is affected, followed by a manual keyboard review.
5. Run the repository-level build and the checks required by Gate 0.

## Completion Evidence

- **Completed:** 2026-08-31.
- **Deliverable:** `.github/workflows/ci.yml` with three independent, cached
  validation slices:
  - **`.NET build and tests`** — Ubuntu runner, .NET 10 SDK, NuGet caching,
    an ephemeral SQL Server 2022 container with a per-run generated, masked
    sa password (never committed or persisted), bounded readiness polling,
    then `dotnet build` and `dotnet test` of `SystemUptimeTracker.Tests`
    using the `SystemUptimeTracker__Tests__SqlServer__ConnectionString`
    override.
  - **`Contract tests (v1 wire contracts)`** — golden JSON contract suite
    from `SystemUptimeTracker.Contracts.UnitTests`.
  - **`Web lint, tests, and build`** — Node 24 with npm caching, `npm ci`,
    lint, Vitest (including the portal Zod contract tests), production build.
  - Future slices reserved in the workflow header: generated-OpenAPI check
    (TASK-0209), migrations (TASK-0307), QA journeys (TASK-1108), packaging
    (TASK-0909/TASK-1007).
- **Green-run evidence:** GitHub Actions run 33418707520
  (`pull_request`, 2026-08-31): all three jobs succeeded — .NET tests
  Passed: 158 against the ephemeral SQL Server container, contract tests
  Passed: 66, web 25 test files passed plus production build.
- **Failing-slice evidence:** run 33442875156 (`workflow_dispatch` on the
  throwaway branch `ci/failing-slice-check`, deleted after the check): a
  deliberately failing contract test made the run and the owning
  `Contract tests (v1 wire contracts)` job fail, with the failed test named
  in the job output
  (`Failed DeliberateFailure_BlocksTheContractsJob`), while the `.NET` and
  `Web` slices stayed green — a failing test blocks exactly its owning job
  and the job output identifies the failed slice.

  generated per run and masked; jobs run with `contents: read` permissions.
