# TASK-0201: Create `docs/api-contracts.md` with the complete `/api/v1` route catalog, caller type, authorization policy, status codes, and idempotency behavior

## Objective

Create `docs/api-contracts.md` with the complete `/api/v1` route catalog, caller type, authorization policy, status codes, and idempotency behavior.

This task contributes to [EPIC-02: Versioned Contracts](../epics/EPIC-02.md)
and must preserve the epic outcome: Freeze interoperable request, response, error, authentication, idempotency, and pagination contracts before API and agent implementations diverge.

## Completion Evidence

- **Completed:** 2026-08-30.
- **Deliverable:** [docs/api-contracts.md](../../api-contracts.md) — the
  accepted `/api/v1` route catalog. 54 routes across seven groups (health,
  auth/tokens, device-account administration, registration/heartbeats, owner
  machine reads, power, locations/devices/associations), each appearing
  exactly once with caller type, authorization policy (`OwnerOnly` /
  `DeviceTelemetry`), success and error status codes, idempotency behavior,
  and owning epic. Conventions cover Problem Details, correlation headers,
  UTC timestamps, units, bounded pagination, and agent retry classification.
  Existing pre-v1 baseline routes are cataloged separately with their
  disposition owners; no new client may depend on them.
- **Validation:** `dotnet build SystemUptimeTracker.sln` — 0 errors;
  `dotnet test` SystemUptimeTracker.Contracts.UnitTests — 65/65 passed.
- **Security review:** Every non-health route requires authentication; auth
  entry points are rate-limited/lockout-protected; token/credential responses
  are specified to exclude stored secrets.
