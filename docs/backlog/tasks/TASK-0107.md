## Completion Evidence

- **Completed:** 2026-08-30.
- **Deliverable:** A
  [Configuration And Environments](../../architecture-overview.md#configuration-and-environments)
  section in `architecture-overview.md` defining: environment names
  (`Development`, `Testing`, `Staging`, `Production`), .NET configuration
  precedence (appsettings → environment appsettings → user secrets →
  environment variables → command line, with `__` env-var and `--` Key Vault
  mapping), web `.env.example`/`.env.local` rules, planned agent
  configuration and protected-state locations, the no-secrets-in-committed-
  settings rule, and the fail-fast startup-validation requirement for new
  components.
- **Verified existing enforcement (no code change needed):** API options use
  `ValidateDataAnnotations()` + `ValidateOnStart()`
  (`RegisterDependentServices.cs`); missing connection strings throw
  actionable `InvalidOperationException`s in the API (`RepositoriesResolver`),
  AppHost (`ResolveEnvironmentVariableValue`), and design-time factory; QA
  automation rejects placeholder and main-database connection strings.
  Covered by existing tests, including
  `DesignTimeApplicationDbContextFactory_WhenConnectionStringMissing_ThrowsClearConfigurationError`
  and the `ResolveRuntimeAutomationDatabaseConnectionString_*` tests — all
  passing in the recorded runs (158/158, 43/43).
- **Verified no committed secrets:** committed settings carry placeholders
  only (`Replace-Key-From-Secrets.json`, `__SET_IN_USER_SECRETS_OR_ENV__`);
  only `.env.example` is git-tracked among the web env files.
- **Validation:** `dotnet build` — 0 errors; `dotnet test` — 158/158 and
  43/43 passed; `npm run verify` — 106 passed, 8 skipped.
- **Security review:** The documented rules make secret placement explicit
  (user secrets/env/secret store; protected agent state; no installer
  command-line credentials).
