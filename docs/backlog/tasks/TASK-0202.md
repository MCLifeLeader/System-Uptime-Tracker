# TASK-0202: Define machine registration request/response DTOs, durable `AgentId`, registration status, assigned `MachineId`, and conflict behavior

## Objective

Define machine registration request/response DTOs, durable `AgentId`, registration status, assigned `MachineId`, and conflict behavior.

This task contributes to [EPIC-02: Versioned Contracts](../epics/EPIC-02.md)
and must preserve the epic outcome: Freeze interoperable request, response, error, authentication, idempotency, and pagination contracts before API and agent implementations diverge.

## Dependency Context

### Prerequisites

- [TASK-0102](./TASK-0102.md): Decide whether `SystemUptimeTracker.Common` becomes the contracts library or whether to add `SystemUptimeTracker.Contracts`

### Tasks Unblocked

- [TASK-0207](./TASK-0207.md): Define idempotency keys: `AgentId + SequenceNumber` for heartbeats and meter identity plus `MessageId` for readings
- [TASK-0209](./TASK-0209.md): Generate or maintain the API OpenAPI document and add a compatibility test for the accepted v1 surface
- [TASK-0301](./TASK-0301.md): Define the telemetry `DbContext` ownership and migration strategy alongside the existing Identity context
- [TASK-0501](./TASK-0501.md): Implement the selected machine registration workflow, including pre-created records, durable `AgentId`, status transitions, and device-account assignment
- [TASK-0701](./TASK-0701.md): Create `SystemUptimeTracker.Agent.Core` and its unit-test project with no Windows Service or systemd hosting dependency
