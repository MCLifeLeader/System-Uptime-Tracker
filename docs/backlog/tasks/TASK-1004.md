# TASK-1004: Implement idempotent install/upgrade with versioned staging, ownership, permissions, daemon reload, enable/start, bounded readiness, and rollback

## Objective

Implement idempotent install/upgrade with versioned staging, ownership, permissions, daemon reload, enable/start, bounded readiness, and rollback.

This task contributes to [EPIC-10: Ubuntu Systemd Delivery](../epics/EPIC-10.md)
and must preserve the epic outcome: Produce a least-privilege Ubuntu daemon artifact and repeatable systemd install, upgrade, rollback, and uninstall workflow.

## Dependency Context

### Prerequisites

- [TASK-1003](./TASK-1003.md): Configure self-contained single-file `linux-x64` publishing without trimming and include unit, configuration template, install/uninstall scripts, and README

### Tasks Unblocked

- [TASK-1005](./TASK-1005.md): Harden the unit with an unprivileged account, restricted writable paths, `NoNewPrivileges`, private temp, filesystem protection, restart policy, and network ordering
- [TASK-1006](./TASK-1006.md): Implement uninstall that disables/removes the unit and releases while retaining durable state unless explicit purge is requested
- [TASK-1007](./TASK-1007.md): Add disposable Ubuntu lifecycle automation for install, repeat install, upgrade, rollback, reboot/autostart, restart recovery, stop, uninstall, and retained state

## Acceptance Criteria

- Disposable Ubuntu tests cover first install, rerun, upgrade, and failed-start rollback.
- All prerequisite behavior remains passing after this change.
- No credentials, API keys, refresh tokens, or sensitive configuration values
  are committed, persisted in plaintext, or emitted to logs.
- Failures are explicit and actionable; the implementation does not silently
  discard telemetry, authorization failures, migration errors, or installer
  errors.
