# TASK-1208: Extend API and database health/metrics with power ingestion count, failures, duplicates, and last-seen state

## Objective

Extend API and database health/metrics with power ingestion count, failures, duplicates, and last-seen state.

This task contributes to [EPIC-12: Power Telemetry Foundation](../epics/EPIC-12.md)
and must preserve the epic outcome: Register power meters independently and persist idempotent readings without coupling machine uptime to power availability.

## Dependency Context

### Prerequisites

- [TASK-1207](./TASK-1207.md): Add owner read endpoints for current meter state and paginated historical readings with deterministic time ordering

### Tasks Unblocked

- [TASK-1402](./TASK-1402.md): Standardize trace/correlation IDs and structured logs across portal, API, agent, heartbeat, and reading operations
- [TASK-1405](./TASK-1405.md): Define actionable metrics and alert thresholds for ingestion failure, auth failure, offline machines, queue age, migration failure, and inactive meters

## Scope

### Included

- Extend API and database health/metrics with power ingestion count, failures, duplicates, and last-seen state.
- Update the owning implementation, tests, configuration, and maintained
  documentation needed to make the behavior complete.

  versioned contract change.

### Excluded

- Opportunistic refactors that do not contribute to the objective or its

## Acceptance Criteria

- Operational checks distinguish a healthy API from an inactive or failing meter.
- All prerequisite behavior remains passing after this change.
- No credentials, API keys, refresh tokens, or sensitive configuration values
  are committed, persisted in plaintext, or emitted to logs.
- Failures are explicit and actionable; the implementation does not silently
  discard telemetry, authorization failures, migration errors, or installer
  errors.
