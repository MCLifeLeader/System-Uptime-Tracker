# TASK-0205: Define owner read and administration contracts for device accounts, machines, sessions, and telemetry with bounded pagination and filtering

## Objective

Define owner read and administration contracts for device accounts, machines, sessions, and telemetry with bounded pagination and filtering.

This task contributes to [EPIC-02: Versioned Contracts](../epics/EPIC-02.md)
and must preserve the epic outcome: Freeze interoperable request, response, error, authentication, idempotency, and pagination contracts before API and agent implementations diverge.

## Completion Evidence

- **Completed:** 2026-08-30.
- **Deliverable:** `SystemUptimeTracker.Contracts` owner read/administration
  contracts: `V1/PagedResponse<T>` and `V1/PaginationDefaults` (default 50,
  maximum 200, 1-based; oversized requests rejected with 400),
  `V1/DeviceAccounts/*` (`DeviceAccountSummary` with API-key metadata but no
  secret material, `CreateDeviceAccountRequest`,
  `UpdateDeviceAccountRequest`, string-serialized
  `AllowedAuthenticationMethods`), `V1/Machines/*` (`MachineSummary` with
  nullable pre-registration fields, `CreateMachineRequest`,
  `UpdateMachineRequest`), `V1/Heartbeats/HeartbeatSummary`, and
  `V1/Sessions/*` (`RuntimeSessionSummary`, `SessionEndReason`).
  Deterministic per-endpoint ordering and bounded date windows are recorded
  in [docs/api-contracts.md](../../api-contracts.md); per TASK-0002 there is
  no per-owner filtering in any owner contract.
- **Tests:** `OwnerContractTests` pin the pagination bounds, the page
  envelope golden shape, nullable pre-created-machine fields, the running
  session round trip, and stable enum strings — part of the 65/65 passing
  run.
- **Validation:** `dotnet test` Contracts.UnitTests — 65/65 passed;
  `dotnet build SystemUptimeTracker.sln` — 0 errors.
- **Security review:** `DeviceAccountSummary` exposes issuance metadata only;
  no owner contract carries credential or hash fields.
