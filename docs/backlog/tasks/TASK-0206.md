# TASK-0206: Define power-meter registration, power reading, location, monitored-device, and effective-dated association contracts

## Objective

Define power-meter registration, power reading, location, monitored-device, and effective-dated association contracts.

This task contributes to [EPIC-02: Versioned Contracts](../epics/EPIC-02.md)
and must preserve the epic outcome: Freeze interoperable request, response, error, authentication, idempotency, and pagination contracts before API and agent implementations diverge.

- [TASK-0102](./TASK-0102.md): Decide whether `SystemUptimeTracker.Common` becomes the contracts library or whether to add `SystemUptimeTracker.Contracts`

### Tasks Unblocked

- [TASK-1201](./TASK-1201.md): Implement `PowerMeter` and `PowerReading` entities, audit fields, connection type, status, and secret reference without storing polling credentials
- [TASK-1205](./TASK-1205.md): Implement authenticated power-reading ingestion with supported units, server receipt time, payload/version limits, and idempotency

- **Completed:** 2026-08-30.
- **Deliverable:** `SystemUptimeTracker.Contracts` power-domain contracts:
  `V1/Power/*` (`CreatePowerMeterRequest`/`UpdatePowerMeterRequest`/
  `PowerMeterSummary` with `MeterConnectionType`, unique
  vendor + external-ID identity, and secret-store `authenticationReference`

  `EndAssociationRequest`, meter location placement and history).

  relationship examples; prove the reading payload and association contracts

  `dotnet build SystemUptimeTracker.sln` — 0 errors.
